# DSC AzDoProcessField Resource

## Syntax

```PowerShell
AzDoProcessField [string] #ResourceName
{
    ProcessName            = [String]$ProcessName
    WorkItemTypeName       = [String]$WorkItemTypeName
    FieldName              = [String]$FieldName
    [ FieldReferenceName   = [String]$FieldReferenceName ]
    [ FieldType            = [String] {'string','integer','boolean','dateTime','html','picklistString','picklistInteger','identity','double','plainText','treePath'} ]
    [ PicklistName         = [String]$PicklistName ]
    [ IsRequired           = [Boolean]$IsRequired ]
    [ DefaultValue         = [String]$DefaultValue ]
    [ ReadOnly             = [Boolean]$ReadOnly ]
    [ Ensure               = [String] {'Present', 'Absent'} ]
}
```

## Properties

### Common Properties

- **ProcessName**: The name of the inherited process. Mandatory.
- **WorkItemTypeName**: The display name of the work item type. Mandatory.
- **FieldName**: The display name of the field. This is the key property.
- **FieldReferenceName**: The reference name of an *existing* field to attach, for example `Microsoft.VSTS.Common.Priority`. Omit when creating a new custom field.
- **FieldType**: The type for a new custom field.
- **PicklistName**: The picklist backing a picklist-typed field. Declare it with `AzDoPicklist` and use `DependsOn`.
- **IsRequired**, **DefaultValue**, **ReadOnly**: The per-work-item-type settings.
- **Ensure**: Whether the field should be on the work item type.

## Additional Information

### A field exists at two levels — this resource manages the second

The **field definition** is organization-scoped and shared: its name and type belong to the organization, and changing them would change the field in every work item type that uses it. What is **per-work-item-type** is whether the field is required, its default value and whether it is read-only — and those are what this resource reconciles.

That is why `FieldName` and `FieldType` are not treated as drift once the field exists.

### Reference names are assigned, not chosen

A new custom field's reference name is generated by Azure DevOps from its display name and cannot be specified. The resource therefore matches by display name and reads the reference name back for subsequent updates. `FieldReferenceName` is for the other case — attaching a field that already exists.

### Removing is not deleting

Removing a field from a work item type detaches it. The definition survives in the organization and the data already stored on existing work items is retained, just no longer shown, so re-adding the field brings the values back into view.

A picklist-typed field whose `PicklistName` cannot be resolved is reported rather than created, so a field is never left pointing at nothing.

## Examples

## Example 1: Sample Configuration using AzDoProcessField Resource

``` PowerShell
Configuration ExampleConfig {
    Import-DscResource -ModuleName 'AzureDevOpsDscNative'

    Node localhost {
        AzDoPicklist Severity {
            Ensure       = 'Present'
            PicklistName = 'Severity'
            Items        = @('1 - Critical', '2 - High', '3 - Medium', '4 - Low')
        }

        AzDoProcessField IncidentSeverity {
            Ensure           = 'Present'
            ProcessName      = 'Contoso Agile'
            WorkItemTypeName = 'Incident'
            FieldName        = 'Severity'
            FieldType        = 'picklistString'
            PicklistName     = 'Severity'
            IsRequired       = $true
            DependsOn        = '[AzDoPicklist]Severity'
        }
    }
}

Start-DscConfiguration -Path ./ExampleConfig -Wait -Verbose
```

## Example 2: Sample Configuration using Invoke-DSCResource

``` PowerShell
# Return the current configuration for AzDoProcessField
$properties = @{
    ProcessName      = 'Contoso Agile'
    WorkItemTypeName = 'Incident'
    FieldName        = 'Severity'
}

Invoke-DscResource -Name 'AzDoProcessField' -Method Get -Property $properties -ModuleName 'AzureDevOpsDscNative'
```

## Example 3: Sample Configuration using Dsc.PipelineRunner

``` YAML
parameters: {}

variables: {}

resources:
- name: Incident Severity Field
  type: AzureDevOpsDscNative/AzDoProcessField
  dependsOn:
    - AzureDevOpsDscNative/AzDoPicklist/Severity Picklist
  properties:
    ProcessName: Contoso Agile
    WorkItemTypeName: Incident
    FieldName: Severity
    FieldType: picklistString
    PicklistName: Severity
    IsRequired: true
    Ensure: Present
```

Pipeline runner initialization:

``` PowerShell

Import-Module Dsc.PipelineRunner

$params = @{
```
